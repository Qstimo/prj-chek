# CAIRN — тёмная тема «спокойное стекло»: дизайн

Дата: 2026-09-02 · Статус: согласован · Основание: ревью текущего оформления `apps/web`, выбор направления с визуальными макетами (`.superpowers/brainstorm/295921-1788354019`)

## 1. Объём и мотивация

Этапы 1–8 сознательно оставили интерфейс «каркасным»: светлая палитра из девяти токенов в `globals.css`, без глубины и фирменного характера. Задача — единая тёмная тема с фиолетовым акцентом в сдержанной эстетике Apple: глубокий фон с мягким свечением у верхнего горизонта, едва прозрачные «стеклянные» поверхности, ровный фиолетовый акцент, читаемые таблицы.

Из трёх рассмотренных направлений (нейтральный графит, фиолетовый сумрак, стекло и свечение) выбрано «стекло и свечение» в спокойной калибровке C1: без фиолетовых ореолов у теней, без градиентных кнопок, свечение только фоновое. Отклонённая калибровка C2 (выразительные ореолы и градиенты) зафиксирована как антицель: CAIRN — ежедневный рабочий инструмент, эффекты не должны конкурировать с данными.

Только тёмная тема. Светлой темы и переключателя нет; палитра задаётся в `:root` без `.dark`-классов и `prefers-color-scheme`. Токены именуются семантически, поэтому светлую тему при необходимости можно добавить позже переопределением значений — но это вне объёма.

Изменения касаются только оформления: CSS-токены, Tailwind-конфигурация и классы в компонентах. Разметка-логика, API, права и тесты поведения не меняются.

## 2. Токены

`globals.css` расширяется с 9 до ~15 переменных. Значения в HSL-компонентах (как сейчас), прозрачные поверхности — через синтаксис `hsl(var(--x) / alpha)` в Tailwind-конфигурации.

| Токен | Значение (ориентир) | Назначение |
| --- | --- | --- |
| `--background` | `hsl(253 27% 7%)` ≈ `#0f0d18` | фон страницы |
| `--foreground` | ≈ `#f2f0fa` | основной текст |
| `--muted` | белый / 6% | приглушённая заливка (было `bg-muted`) |
| `--muted-foreground` | ≈ `#8b86a0` | вторичный текст, контраст ≥ AA к фону |
| `--surface` | белый / 4–5% | стеклянные карточки, таблицы, панели |
| `--surface-strong` | белый / 8% | ховеры и активные состояния поверхностей |
| `--border` | белый / 8% | границы по умолчанию |
| `--border-strong` | белый / 14% | границы при ховере и фокусе |
| `--primary` | ≈ `#7c5cf0` | кнопки действий, активные элементы |
| `--primary-foreground` | белый | текст на акценте |
| `--accent-soft` | фиолетовый / ~22% | заливка активного таба, бейджа «Работает» |
| `--ring` | фиолетовый | кольцо клавиатурного фокуса |
| `--destructive` | красный, перебалансированный под тёмный | опасные действия |
| `--destructive-foreground` | белый | текст на красном |
| `--radius-card` | 12px | карточки, таблицы, панели (`rounded-lg`) |
| `--radius-control` | 8px | кнопки, поля, мелкие элементы (`rounded-md`) |

Дополнительно на `body`:

- фиксированное радиальное свечение — `radial-gradient` фиолетового (~18% непрозрачности) у верхнего горизонта поверх `--background`, `background-attachment: fixed`, чтобы свечение не скроллилось;
- `color-scheme: dark` — нативные контролы, скроллбары и автозаполнение браузера становятся тёмными.

Семантические цвета темой не считаются и не трогаются: зелёный/янтарный/красный/серый в `StatusIndicator`, янтарная `WarningsPanel`. На тёмном фоне они остаются читаемыми без правок.

## 3. Глубина и форма

- Поверхность (карточка, таблица, панель) = `--surface` + граница `--border` + радиус `--radius-card`. Одна мягкая нейтральная тень для приподнятых поверхностей. Фиолетовых теней и ореолов нет — это граница между C1 и отклонённой C2. Единственный текущий радиус `--radius` (0.5rem, `rounded-md`) заменяется парой: `borderRadius.md → var(--radius-control)`, `borderRadius.lg → var(--radius-card)` в Tailwind-конфигурации.
- Навигация — стеклянная полоса: полупрозрачный фон, `backdrop-blur`, прилипает к верху (`sticky top-0`), нижняя граница `--border`.
- Кнопки: ровная заливка `--primary`, радиус 8px; вторичные — `--surface` с границей. Бейджи — pill (`rounded-full`).
- Фокус: видимое кольцо `--ring` на клавиатурной навигации у всех интерактивных элементов.

## 4. Типографика

Системный стек без внешних шрифтов (инвариант self-hosted, и это эппловский путь): `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, system-ui, sans-serif`. Заголовки — вес 600–650 и `tracking-tight`. Моноширинный стек — ключи переменных, приёмные адреса, токены.

## 5. Точечные правки компонентов

Токены закрывают ~90% экранов автоматически (55 использований `border-border`, 23 `bg-primary` и т. д.). Руками — компоненты, где нужны новые классы:

1. `AppNav` — стеклянная прилипающая полоса с блюром.
2. `ProjectCard` — стеклянная карточка, ховер через `--surface-strong`/`--border-strong` вместо `hover:border-primary`.
3. `ProjectSections` — активный таб на `--accent-soft`, неактивные — `muted-foreground`.
4. `VariableTable`, `AuditTable`, `UserList` — таблица внутри стеклянного контейнера со скруглением и разделителями `--border`.
5. `TextField` и формы — тёмные поля на `--surface`, граница `--border` → `--border-strong` при фокусе + кольцо `--ring`.
6. `LIFECYCLE_STYLES` — «Работает»: `--accent-soft` с фиолетовым текстом вместо чёрной заливки `bg-primary`; остальные состояния — приглушённые, как сейчас.
7. Страница логина — свечение по центру экрана; единственное место, где стеклу позволено быть чуть выразительнее.

## 6. Проверка

- Существующие тесты — поведенческие; падать не должны. Единичные ассерты на классы обновляются вместе с правкой компонента.
- `pnpm test`, `pnpm typecheck`, `pnpm build`.
- Визуальный смоук в браузере: логин, сводка проектов, все шесть секций, а также страницы вне основного layout — публичный роадмап (`app/roadmap/[token]`) и приглашение (`app/invite/[token]`): у них нет `AppNav`, и фоновое свечение `body` нужно проверить отдельно. Плюс администрирование: журнал, пользователи, безопасность, доступы. Контраст текстовых пар — по WCAG AA.
- В секции «Документация» отдельно проверить компонент `Markdown`: блоки кода на заливке `bg-muted` (белый / 6%) должны оставаться читаемыми.

## 7. Вне объёма

Светлая тема и переключатель; изменение структуры компонентов и переход на shadcn/ui; анимации и переходы сверх имеющегося `transition`; изменение семантических цветов статусов.

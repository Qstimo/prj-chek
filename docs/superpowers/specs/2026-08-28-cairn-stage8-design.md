# CAIRN — этап 8 «MCP-доступ для агентов»: дизайн

Дата: 2026-08-28 · Статус: согласован · Основание: `project-registry-spec [eTsSSz].md`, раздел 10, пункт 8

## 1. Объём

Финальный этап: MCP-сервер, который агент на машине разработчика (Claude, Cursor и подобные) подключает адресом и токеном без обвязки (ТЗ 7.2). Токен агента — субъект вида `agent_token` в общей таблице выдач, заложенной этапом 1: модель прав не меняется, токен физически не может получить больше выданного (ТЗ 7.3).

Инварианты ТЗ 7 соблюдаются буквально:

- **только чтение** — ни одного пишущего инструмента; иначе документация за месяц превращается в свалку сгенерированного текста (ТЗ 7.2);
- **закрытый профиль по умолчанию** (ТЗ 7.3): инфо, документация, роадмап, хроника — чтение; переменные — метаданные; инфраструктура — метаданные (список окружений и статус);
- **значения переменных — отдельная настройка токена, выключенная по умолчанию** (ТЗ 7.3, 7.4);
- **каждый запрос агента — в журнал с пометкой машинного доступа** (ТЗ 7.4) — в отличие от людей, у которых чтения не журналируются;
- **токен привязан к проекту, имеет срок жизни, отзывается в один клик** (ТЗ 7.4).

Транспорт — официальный `@modelcontextprotocol/sdk` (Streamable HTTP): именно его клиенты подключают без обвязки, а самодельный JSON-RPC разошёлся бы с эволюцией протокола. Это осознанная новая зависимость.

## 2. Модель данных

**`agent_tokens`**: `id`, `subject_id` (unique, restrict → `subjects`), `project_id` (restrict), `label`, `token_hash`, `can_reveal_variables` (default false), `expires_at` (not null), `created_at`, `last_used_at` (nullable).

Токен хранится хэшированным (sha256, как сессии) и показывается один раз при создании — в отличие от приёмного адреса его не нужно никому пересылать. Срок жизни обязателен: при создании задаётся в днях (по умолчанию 90). Отзыв — штатный `revoked_at` субъекта: все проверки прав немедленно отказывают.

`can_reveal_variables` — колонка токена, а не уровень выдачи, намеренно: раскрытие значения агенту разрешается только парой «уровень позволяет И флаг включён». Держать флаг в выдачах значило бы поднять токену уровень `read` на переменных — и человеческий механизм раскрытия стал бы доступен агенту без отдельного решения.

## 3. Создание токена

Суперадмин: `POST /projects/:id/agent-tokens { label, ttlDays?, canRevealVariables? }`. В одной транзакции: субъект `agent_token` (label = имя токена), строка `agent_tokens`, шесть выдач закрытого профиля:

| Секция | Уровень |
|---|---|
| info, docs, roadmap, chronicle | read |
| variables, infrastructure | metadata |

Ответ — токен открытым текстом (единственный раз) + готовый фрагмент конфигурации клиента. Журнал: `agent_token.created`; переключение флага (`PATCH`) — `agent_token.updated` с именем поля; отзыв (`DELETE`) — `agent_token.revoked`. Управление и просмотр списка — суперадмин, экран доступов проекта.

## 4. MCP-сервер

`POST /api/mcp` — Streamable HTTP в stateless-режиме (каждый запрос самодостаточен; состояние сессий SDK не хранится — совместимо с несколькими экземплярами API). Аутентификация: `Authorization: Bearer <токен>` → хэш → живой (`revoked_at IS NULL`), непросроченный токен; иначе `401`. Успешный вызов обновляет `last_used_at`.

Инструменты (ТЗ 7.2) — все работают через существующие репозитории с `RequestSubject` токена, обходов модели прав нет:

| Инструмент | Что делает | Через |
|---|---|---|
| `get_project_info` | паспорт проекта | `ProjectsRepository.findById` |
| `search_docs(query)` | поиск по заголовкам и содержимому, фрагменты | `DocsRepository` + ILIKE |
| `read_doc_page(title)` | содержимое страницы | `DocsRepository` |
| `get_roadmap` | версии, чекпоинты, стадия | `RoadmapRepository` |
| `read_chronicle` | лента событий | `ChronicleRepository` |
| `list_variable_keys(environment?)` | ключи с описаниями, без значений | `VariablesRepository.list` |
| `get_status` | агрегат статуса | `StatusRepository` |
| `reveal_variable(environment, key)` | значение переменной | `VariablesService.reveal` |

`reveal_variable` **регистрируется только при включённом флаге** — без него инструмента нет в `tools/list` вовсе, а прямой вызов отвечает ошибкой. Профиль даёт переменным `metadata`, поэтому проверка reveal для агента выполняется отдельной веткой: флаг включён → чтение значения от лица токена с записью `variable.revealed` (штатной).

**Журнал**: каждый вызов инструмента пишет `agent.tool_called` с именем инструмента и аргументами; значения переменных в запись не попадают. `subjectKind: agent_token` — пометка машинного доступа. Отказ аутентификации не журналируется (субъекта нет).

Обо всех рисках ТЗ 7.4 (утечка в контекст модели, внедрение инструкций через документацию) система отвечает архитектурой: закрытый профиль, флаг значений, отсутствие записи.

## 5. Интерфейс

Панель «Токены агентов» на экране доступов проекта (`/projects/[id]/access`, суперадмин): список токенов (имя, срок, последний вызов, признак доступа к значениям), создание (имя + срок + флаг с предупреждением о рисках), показ созданного токена один раз с фрагментом конфигурации, переключение флага, отзыв с подтверждением.

## 6. Тестирование

- **Схема** + инварианты (обе-таки одна новая таблица).
- **Сервис токенов** (Testcontainers): создание = субъект + 6 выдач профиля (проверяются уровни каждой секции); отзыв гасит субъект; аутентификация по хэшу: валидный/мусорный/отозванный/просроченный.
- **MCP e2e**: JSON-RPC поверх supertest — `initialize`, `tools/list` (без флага нет `reveal_variable`, с флагом есть), `tools/call` каждого инструмента; `401` без/с плохим токеном; журнал содержит `agent.tool_called` с `subjectKind: agent_token`; `reveal_variable` пишет `variable.revealed`; инструменты не достают чужой проект.
- **Сквозная (`scripts/e2e.mjs`)**: создать токен → JSON-RPC `initialize`+`tools/call get_project_info` и `list_variable_keys` (значений нет в ответе) → включить флаг → `reveal_variable` возвращает значение → журнал содержит машинные записи → отзыв → `401`.

# CAIRN — этап 7 «Документация»: дизайн

Дата: 2026-08-28 · Статус: согласован · Основание: `project-registry-spec [eTsSSz].md`, раздел 10, пункт 7

## 1. Объём

Реализуется секция «Документация» (ТЗ 3.4): произвольные страницы по проекту — как развернуть, как устроено, что где лежит, к кому обращаться. Отвечает на вопрос «как это устроено сейчас»; история («как мы к этому пришли») остаётся хронике, и смешивать их нельзя. Плюс «поднять запись хроники в страницу документации» (ТЗ 3.6) — второй приёмник, по образцу подъёма в чекпоинт.

Версий у страниц нет: ТЗ требует версии только у переменных, где они защищают секреты. Страница — актуальное состояние; кто и когда правил, фиксирует журнал.

Предложения модели по входящим (ТЗ 5.3) в объём не входят: они остаются за пределами этапов 1–8 как необязательный шаг, требующий интеграции с моделью.

## 2. Модель данных

**`doc_pages`**: `id`, `project_id` (`restrict`), `title`, `content`, `created_by_subject_id` (`restrict`), `created_at`, `updated_at`.

`title` уникален в проекте: две страницы «Развёртывание» — путаница. `content` — Markdown-текст, хранится как есть; интерпретация — забота клиента. Список страниц упорядочен по заголовку.

## 3. Доступ

Секция `Section.Docs` (ТЗ 4.3, строка «Документация»):

| Уровень | Доступно |
|---|---|
| нет строки выдачи | `404` |
| `metadata` | список страниц: заголовок, дата правки |
| `read` | плюс содержимое |
| `write` | создание, правка, удаление |

Проекция через `projectByLevel`: метаданные — `id`, `title`, `updatedAt`; подробность — `content`, `createdAt`. Журнал: `doc_page.created/updated/deleted` — заголовок и перечень изменённых полей; содержимое в журнал не попадает (не секрет, но объёмно и бесполезно в записи).

## 4. API

CRUD `projects/:id/docs` в точности по рисунку хроники: `GET` (список по уровню), `GET /:pageId`, `POST` (`write`), `PATCH /:pageId`, `DELETE /:pageId` с подтверждением на месте в интерфейсе. Принадлежность «проект → страница» сверяется в запросе; чужое — `404`. Контракт — `packages/shared/src/schemas/doc.ts`.

## 5. Markdown — собственная безопасная единица

`apps/web/src/components/Markdown/`:

- **`parseMarkdown(text): Block[]`** — чистая функция. Подмножество: заголовки `#`–`###`, маркированные (`-`) и нумерованные (`1.`) списки, блоки кода ` ``` `, строчный код `` ` ``, `**жирный**`, `*курсив*`, ссылки `[текст](url)`, абзацы. Ссылки принимаются только с `http:`/`https:` — всё прочее (включая `javascript:`) рендерится обычным текстом.
- **`<Markdown content>`** — рендер блоков в React-элементы. `dangerouslySetInnerHTML` не используется нигде: XSS невозможен по построению, а не по фильтрации.

Парсер тестируется отдельно от рендера; зависимостей не добавляется.

## 6. Подъём из хроники

У записи хроники — кнопка «В документацию» рядом с «В чекпоинт», видна при `write` на секции документации (уровень уже приходит в карте секций). Панель на месте: заголовок предзаполнен заголовком записи, содержимое — содержимым записи, оба правятся. Отправка — обычный `POST` страницы; связи между секциями не создаётся, запись хроники остаётся на месте (история не переезжает — ТЗ 3.6 говорит «поднять содержимое выше», а не «перенести»).

## 7. Интерфейс

Страница `/projects/[id]/docs`: список страниц (заголовки с датами), просмотр выбранной с рендером Markdown, при `write` — создание и правка (заголовок + textarea с моноширинным шрифтом), удаление с подтверждением на месте. Ссылка «Документация» — в навигацию секций карточки проекта.

Компоненты: `Markdown/`, `DocPageList/`, `DocPageView/`, `DocPageForm/`, `PromoteToDoc/` (в хронике). Хуки: `useQueryDocs`, `useQueryDocPage`, мутации страниц.

## 8. Тестирование

- **Модульные:** `parseMarkdown` (все конструкции, `javascript:`-ссылка → текст, вложенный строчный код в абзаце), рендер `<Markdown>` по разметке, схемы контракта, компоненты.
- **Testcontainers:** репозиторий (уровни, уникальность заголовка, чужой проект), сервис с журналом (содержимое не в журнале).
- **HTTP e2e** и **блок в матрице доступа** (`metadata` не видит содержимого: `list 404/200/200/200`, `create 404/403/403/201`).
- **Сквозная (`scripts/e2e.mjs`):** страница создана с Markdown-содержимым → гость с `metadata` видит заголовок, но не содержимое → у `read`-уровня содержимое приходит.

## 9. Связь со следующим этапом

Этап 8 включит документацию в профиль токена агента по умолчанию (чтение и поиск по страницам — ТЗ 7.2/7.3); риск внедрения инструкций через документацию (ТЗ 7.4) решается там же — закрытым профилем и отсутствием записи у агентов.

# Роадмап с выезжающей панелью — дизайн

Дата: 2026-09-04. Статус: согласован.

## Цель

Экран роадмапа перестаёт быть списком карточек. На странице остаётся только
диаграмма; вся информация о версии — просмотр, редактирование, чекпоинты —
живёт в панели, выезжающей справа. Под названием каждой версии на диаграмме
появляется дата релиза: фактическая для выпущенной, ожидаемая для остальных.

Затрагиваются: внутренний экран роадмапа, публичная страница роадмапа,
модель данных версии (новое поле фактической даты релиза).

## 1. Модель данных: `releasedDate`

У версии появляется фактическая дата релиза, отдельная от плановой.

- **БД**: колонка `released_date` (`date`, nullable) в `roadmap_versions`,
  миграция Drizzle. Существующие строки получают `NULL` — фактическая дата
  прошлых релизов неизвестна, и это честнее, чем копировать плановую.
- **Shared-схемы** (`packages/shared/src/schemas/roadmap.ts`): поле
  `releasedDate` того же формата, что `plannedDate` (`ГГГГ-ММ-ДД`, nullable):
  - в `roadmapVersionMetadataSchema` — обязательное nullable-поле
    (метаданных достаточно: дата не раскрывает формулировок);
  - в `roadmapVersionCreateSchema` и `roadmapVersionUpdateSchema` —
    опциональное nullable-поле.
- **API**: репозиторий роадмапа сохраняет и отдаёт поле без дополнительной
  логики. Валидация согласованности (дата есть, а состояние не «выпущена»)
  не вводится: поле информационное, сервер принимает любое сочетание.
- **Форма версии** (`VersionForm`): поле «Дата релиза» отображается, только
  когда выбрано состояние «выпущена». При переключении состояния в
  «выпущена» и пустом поле подставляется сегодняшняя дата — пользователь
  может её поправить. При других состояниях поле не отправляется как есть:
  отправляется `releasedDate: null`, чтобы дата не «залипала» от прежнего
  состояния.

## 2. Диаграмма: `RoadmapTimeline`

Диаграмма перестраивается с единого SVG на колонки-кнопки.

- Каждая версия — колонка: `<button>` (при наличии обработчика) или `<div>`.
  Внутри: маленький SVG-кругляшок (та же геометрия: круг-основа, сектор
  прогресса из `sector.ts`, кольцо текущей), под ним название версии
  (переносится, как сейчас), ниже — строка даты.
- Строка даты:
  - состояние «выпущена» и есть `releasedDate` → дата в русском формате
    (`01.12.2026`);
  - состояние «выпущена» без `releasedDate` → строка пустая: фактическая
    дата неизвестна (типовое состояние старых версий после миграции),
    и показывать плановую с «ожидается» для уже выпущенной версии
    было бы ложью;
  - не выпущена и есть `plannedDate` → `ожидается 01.12.2026`;
  - даты нет → строка пустая (высота места сохраняется, чтобы колонки
    не прыгали).
- Формат даты — общая утилита `apps/web/src/utils/format-date.ts`
  (день `ГГГГ-ММ-ДД` → `ru-RU`, с barrel-экспортом в `utils/index.ts`);
  её используют диаграмма и панель. Существующие три места
  с собственным форматированием не трогаем — вне объёма.
- Соединительная горизонтальная линия рисуется позади кругляшков
  (абсолютно позиционированный элемент на уровне их центров).
- Новый необязательный проп `onSelect(versionId)`. Он передан — колонки
  становятся кнопками с `aria-label` вида «Версия v1.0»; не передан —
  колонки статичны (диаграмма пригодна и без панели).
- Тип `TimelineVersion` расширяется полями `plannedDate` и `releasedDate`.

## 3. Панель: `Drawer` и `VersionDrawer`

### `Drawer` — общий компонент

Обёртка над Radix Dialog (`@radix-ui/react-dialog`, уже в зависимостях):

- контент прижат к правому краю, во всю высоту, ширина до 480px
  (на мобильном — вся ширина), внутренняя прокрутка;
- полупрозрачная подложка слева — диаграмма остаётся видна;
- анимация выезда справа (`translate-x`), закрытие по Esc, клику по
  подложке и кнопке-крестику с `aria-label="Закрыть"`;
- фокус-ловушка, `aria`-разметка и блокировка прокрутки — от Radix;
- пропсы: `isOpen`, `onClose`, `title`, `children`.

### `VersionDrawer` — содержимое для версии

Презентационный компонент: версию и права получает пропами, сам данных
не запрашивает и мутаций не владеет — поэтому одинаково работает
на внутреннем экране (данные из кэша TanStack Query) и на публичной
странице (данные пропом из RSC, без TanStack Query и `projectId`).

Пропсы: `version` (метаданные или полная версия — union из shared),
`isCurrent`, `isOpen`, `onClose` и необязательный блок действий записи
`actions`: колбэки `onToggleCheckpoint`, `onAddCheckpoint`,
`onDeleteCheckpoint`, `onSubmitVersion`, `onDeleteVersion` и состояния
форм `isSubmittingVersion`, `versionError`, `isSubmittingCheckpoint`.
Нет `actions` — панель только на просмотр.

Открывается кликом по кругляшку. Два режима:

- **Просмотр** (по умолчанию): название, состояние (подписи —
  `STATE_LABELS`), плановая и фактическая даты, прогресс (`3 из 5`),
  список чекпоинтов (`CheckpointList`). С `actions`: галочки чекпоинтов
  переключаются сразу (мутация без подтверждения), форма добавления
  чекпоинта (существующий `CheckpointForm`), удаление чекпоинта, кнопки
  «Редактировать» и «Удалить версию». Удаление версии — с двухшаговым
  подтверждением, как в нынешнем `VersionCard`: оно уносит все чекпоинты.
  Без `actions` — всё то же без органов управления: галочки
  нередактируемы, кнопок нет.
- **Редактирование** (только с `actions`): вместо шапки просмотра —
  `VersionForm` с текущими значениями, включая `releasedDate`
  в `initial`; блок чекпоинтов остаётся видимым под формой. После
  сохранения панель возвращается в режим просмотра. Отмена — тоже
  возврат в просмотр.
- **Уровень «метаданные»**: API отдаёт версию без чекпоинтов (union
  в `roadmapResponseSchema`), различается type guard'ом `isDetailed`.
  Панель открывается на просмотр: паспорт и прогресс есть, блока
  чекпоинтов нет.

Подписи `STATE_LABELS` и компонент `CheckpointList` переезжают
из директории `VersionCard` в директорию `VersionDrawer` (с barrel-
экспортом); `VersionForm` начинает импортировать `STATE_LABELS` оттуда.

## 4. Внутренний экран: `RoadmapScreen`

- Остаются: диаграмма (включая нынешнее пустое состояние «Версий пока
  нет.»), кнопка «Добавить версию», панель публичной ссылки.
- Сетка `VersionCard` и инлайн-формы уходят. После переезда
  `STATE_LABELS` и `CheckpointList` в `VersionDrawer` (раздел 3) файл
  `VersionCard.tsx` не используется нигде — удаляется вместе с тестами
  и директорией (перед удалением проверить использования).
- Состояние экрана: `selectedVersionId: string | null` (открывает
  `VersionDrawer`) и `isCreating: boolean` (открывает `Drawer`
  с заголовком «Новая версия» и `VersionForm` создания; после успешного
  создания панель закрывается).
- Экран сам находит выбранную версию по id в данных запроса роадмапа
  и передаёт её панели пропом; если версия исчезла из данных (удалена
  в другой вкладке) — панель закрывается. Колбэки `actions` экран
  собирает из существующих mutation-хуков.
- Одновременно открыта максимум одна панель: открытие одной сбрасывает
  другую.

## 5. Публичная страница: `PublicRoadmapView`

Та же диаграмма с датами и кликами; `VersionDrawer` открывается без
`actions` — только просмотр. Публичная схема уже содержит полные версии
с чекпоинтами (и `releasedDate` попадёт в неё автоматически: она строится
на `roadmapVersionDetailSchema`), дополнительных запросов не нужно.
Выбранную версию хранит и передаёт пропом сам `PublicRoadmapView`.

## 6. Тестирование (TDD)

Сначала падающий тест, затем реализация:

- **shared**: `releasedDate` в схемах — принимается, валидируется формат,
  nullable;
- **api**: репозиторий роадмапа сохраняет и отдаёт `releasedDate`
  (создание, правка, выборка) — интеграционные тесты Testcontainers;
- **web**:
  - `formatDate` — формат дня по `ru-RU`;
  - `RoadmapTimeline` — рендер дат по правилам раздела 2 (включая
    выпущенную без даты), вызов `onSelect` по клику и с клавиатуры,
    статичность без `onSelect`;
  - `Drawer` — открытие/закрытие (Esc, подложка, крестик), заголовок;
  - `VersionDrawer` — просмотр с `actions` и без, версия-метаданные без
    блока чекпоинтов, переключение галочек, переход в редактирование
    и обратно, удаление;
  - `VersionForm` — появление поля «Дата релиза» при состоянии «выпущена»,
    подстановка сегодняшней даты, отправка `null` при других состояниях,
    `releasedDate` из `initial`;
  - `RoadmapScreen` и `PublicRoadmapView` — открытие панелей, создание
    версии через панель, взаимное вытеснение панелей, закрытие при
    исчезновении версии из данных.

## Вне объёма

- Отдельный маршрут или параметр URL для открытой панели (deep-link).
- Перестановка версий и чекпоинтов перетаскиванием.
- Изменения публикации роадмапа и панели публичной ссылки.
- Перевод существующих мест форматирования дат (`ChronicleEntry`,
  `AgentTokenRow`, `DocPageList`) на общий `formatDate`.
